## v1.1.0 में नया क्या है

लेयर 7 — **एएसटी-जागरूक बहुभाषी नाम परिवर्तन**। `forkctl rename plan` पहचान फ़ाइलों, कोड प्रतीकों (एएसटी-ग्रीप के माध्यम से 26 भाषाएँ), और गैर-कोड पाठ्य सतहों में समीक्षा योग्य अंतर उत्पन्न करता है। `forkctl rename apply` ट्री का स्नैपशॉट लेता है, सभी पास चलाता है, लॉकफ़ाइलें पुन: उत्पन्न करता है, और किसी भी बाइनरी चीज़ के लिए एक एसेट-पुनरुत्पादन मेनिफ़ेस्ट छोड़ देता है। `forkctl rename rollback` नवीनतम स्नैपशॉट को पुनर्स्थापित करता है। कोई `sed` श्रृंखला नहीं। शब्द-सीमा सही। केसिंग-जागरूक।

## फ़ॉर्कctl क्या करता है

GitHub रिपॉजिटरी को फ़ॉर्क करना एक क्लिक है। इसे अपनाना — फ़ॉर्क बनाम टेम्पलेट चुनना, संगठन नीति से निपटना, एसिंक्रोनस निर्माण की प्रतीक्षा करना, अपस्ट्रीम सिंक्रनाइज़ेशन को कॉन्फ़िगर करना, परिणाम को वास्तव में चलाने योग्य बनाना — बाकी सब कुछ है।

फ़ॉर्कctl बाकी सब कुछ का प्रबंधन करता है।

| लेयर | यह क्या करता है |
|--------------|-----------------------------------------------------------------------------------------------|
| आकलन | किसी रिपॉजिटरी की अपनाने की तैयारी का मूल्यांकन करें, फ़ॉर्क बनाम टेम्पलेट बनाम आयात की अनुशंसा करें, स्रोत-साइड सुधारों का प्रस्ताव करें। |
| निष्पादन | एक ट्रैक किए गए एसिंक्रोनस ऑपरेशन के रूप में कॉपी बनाएं। संगठन/उद्यम फ़ॉर्क-नीति अवरोधकों को शुरुआत में ही सामने लाता है। |
| बूटस्ट्रैप | प्रोफ़ाइल-संचालित अनुवर्ती कार्रवाई — अपस्ट्रीम कॉन्फ़िगरेशन, रीडमी अपडेट, ड्रिफ्ट स्कैन, चलाने योग्य हैंडऑफ़। |
| सिंक | GitHub मर्ज-अपस्ट्रीम एपीआई को कॉल करता है। ईमानदारी से विचलन की रिपोर्ट करता है। आवश्यकता पड़ने पर पीआर पर वापस आ जाता है। |
| फ़्लीट | अपने फ़ॉर्क की सूची बनाएं, स्वास्थ्य जांच करें और बैच-सिंक करें। |
| रसीदें | प्रत्येक ऑपरेशन का मशीन-पठनीय रिकॉर्ड। स्थानीय SQLite में ऑडिट लॉग। |
| नाम बदलें | एएसटी-जागरूक बहुभाषी नाम परिवर्तन — पहचान फ़ाइलें, कोड प्रतीक, पाठ्य सतहें, लॉकफ़ाइल पुन: उत्पन्न करना। |

## उपयोग के तरीके

फ़ॉर्कctl को एक **एमसीपी सर्वर** (एसटीडीआईओ ट्रांसपोर्ट, क्लाउड कोड और अन्य एमसीपी क्लाइंट के लिए) और एक ही सतह के साथ एक **सीएलआई** दोनों के रूप में शिप किया जाता है।

### एमसीपी

अपने एमसीपी क्लाइंट कॉन्फ़िगरेशन में जोड़ें:

```json
{
  "mcpServers": {
    "forkctl": {
      "command": "npx",
      "args": ["-y", "@mcptoolshop/forkctl", "mcp"],
      "env": { "GITHUB_TOKEN": "ghp_..." }
    }
  }
}
```

### सीएलआई

```bash
npx @mcptoolshop/forkctl assess owner/repo
npx @mcptoolshop/forkctl choose-path owner/repo --goal contribute_upstream
npx @mcptoolshop/forkctl create-fork owner/repo --destination-org my-org
npx @mcptoolshop/forkctl sync my-fork
npx @mcptoolshop/forkctl fleet-health
```

सभी कमांड मशीन-पठनीय आउटपुट के लिए `--json` स्वीकार करते हैं।

## बीस-दो उपकरण
<!-- FORKABLE_COUNTS_END -->

### आकलन
- `forkctl_assess` — अपनाने की तैयारी स्कोर, अवरोधक, ताकत
- `forkctl_choose_path` — फ़ॉर्क | टेम्पलेट | आयात | क्लोन-डिटैच्ड
- `forkctl_make_forkable` — स्रोत रिपॉजिटरी को ठीक करें (डिफ़ॉल्ट: योजना; वैकल्पिक: पीआर)

### निष्पादन
- `forkctl_preflight_policy` — उद्यम/संगठन/रिपॉजिटरी फ़ॉर्क-नीति अवरोधकों का पता लगाएं
- `forkctl_create_fork` — एसिंक्रोनस, ऑपरेशन_आईडी लौटाता है
- `forkctl_create_from_template` — GitHub `/generate` का उपयोग करता है
- `forkctl_check_operation` — किसी भी चल रहे ऑपरेशन को पोल करें

### बूटस्ट्रैप
- `forkctl_bootstrap` — प्रोफ़ाइल-संचालित (योगदानकर्ता / स्टार्टर-किट / आंतरिक-बीज / क्लाइंट-डिलीवरी / प्रयोग)
- `forkctl_configure_upstream` — रिमोट सेट करें, वैकल्पिक सिंक्रनाइज़ेशन वर्कफ़्लो
- `forkctl_scan_drift` — हार्डकोडेड पथ, लीक किए गए गुप्त, कॉपी में पुरानी सीआई संदर्भ
- `forkctl_emit_handoff` — एक सच्चा कलाकृति: यूआरएल, कमांड, चेतावनी, अगला कार्रवाई

### सिंक
- `forkctl_sync` — GitHub मर्ज-अपस्ट्रीम एपीआई
- `forkctl_diagnose_divergence` — पीछे कमिट, जोखिम वाली फ़ाइलें, अनुमानित संघर्ष
- `forkctl_propose_sync_pr` — जब तेज़-फ़ॉरवर्ड विफल हो जाता है तो पीआर-आधारित सिंक्रनाइज़ेशन

### फ़्लीट
- `forkctl_list_forks` — आपका + देखा गया, स्वास्थ्य कॉलम के साथ
- `forkctl_fleet_health` — पुरानी / संघर्षपूर्ण / परित्यक्त
- `forkctl_batch_sync` — सीमित, दर-सीमा-जागरूक

### रसीदें
- `forkctl_receipt` — किसी भी ऑपरेशन का मशीन-पठनीय रिकॉर्ड
- `forkctl_audit_log` — केवल-जोड़ने का इतिहास

### नाम बदलें (लेयर 7 — v1.1.0 में नया)
- `forkctl_rename_plan` — एएसटी-जागरूक नाम परिवर्तन योजनाकार; समीक्षा योग्य अंतर उत्पन्न करता है
- `forkctl_rename_apply` — स्नैपशॉट + पहचान + प्रतीक + पाठ्य + पोस्ट पास लागू करता है
- `forkctl_rename_rollback` — नवीनतम स्नैपशॉट से पुनर्स्थापित करता है

## बूटस्ट्रैप प्रोफ़ाइल

| प्रोफ़ाइल | के लिए | अनुवर्ती कार्रवाई |
|---------------------|--------------------------------------------------------------------|---------------------------------------------------------------------------------|
| `contributor`       | अपस्ट्रीम में पीआर वापस भेजने के लिए फ़ॉर्क करना | अपस्ट्रीम रिमोट, सिंक्रनाइज़ेशन वर्कफ़्लो, योगदानकर्ता रीडमी ब्लॉक, यदि अनुपस्थित है तो पीआर टेम्पलेट। |
| `starter-kit`       | अपने स्वयं के उत्पाद को शुरू करने के लिए एक टेम्पलेट से उत्पन्न। | टेम्पलेट संदर्भ, ताज़ा रीडमी, ताज़ा लाइसेंस प्रॉम्प्ट, .env.example को हटा दें। |
| `internal-seed`     | साझा बीज रिपॉजिटरी की आंतरिक टीम कॉपी। | प्लेसहोल्डर बदलें, आंतरिक CODEOWNERS सेट करें, दृश्यता लॉक करें। |
| `client-delivery`   | वितरण योग्य का प्रति-क्लाइंट फ़ॉर्क। | क्लाइंट-नाम वाली शाखाएँ, सैनिटाइज़्ड इतिहास जाँच, लॉक डिफ़ॉल्ट शाखा। |
| `experiment`        | अस्थायी / अलग कॉपी। | अपस्ट्रीम को अलग करें, रीडमी में प्रयोग के रूप में चिह्नित करें, कोई सिंक्रनाइज़ेशन वर्कफ़्लो नहीं। |

## कॉन्फ़िगरेशन

| चर | आवश्यक | डिफ़ॉल्ट | टिप्पणियाँ |
|----------------------|----------|----------------------------------------------|-------------------------------------------------|
| `GITHUB_TOKEN`       | हाँ | —                                            | `repo`, `workflow`, `read:org` स्कोप |
| `GITHUB_API_URL`     | no       | `https://api.github.com`                     | GHES / ghe.com के लिए |
| `FORKCTL_STATE_DIR` | no       | ओएस उपयोगकर्ता-अवस्था निर्देशिका (`env-paths` के माध्यम से) | जहां SQLite संचालन + ऑडिट डेटाबेस स्थित हैं |

## सुरक्षा

धमकी मॉडल और रिपोर्टिंग नीति के लिए [SECURITY.md](SECURITY.md) देखें। मुख्य बातें:

- `GITHUB_TOKEN` कभी भी लॉग नहीं किया जाता है।
- प्रत्येक टूल इनपुट को ज़ोड के माध्यम से मान्य किया जाता है।
- `make_forkable` डिफ़ॉल्ट रूप से `plan` मोड पर सेट है। `pr` मोड वैकल्पिक है।
- फ़ॉर्कctl कभी भी फ़ोर्स-पुश नहीं करता है, रिपॉजिटरी को हटाता नहीं है, या शाखाओं को हटाता नहीं है।
- कोई टेलीमेट्री नहीं। कॉन्फ़िगर किए गए GitHub एपीआई को छोड़कर कोई आउटबाउंड कॉल नहीं।
